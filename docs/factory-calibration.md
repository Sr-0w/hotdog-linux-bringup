# Factory sensor calibration

Last reviewed: 2026-08-25

Every OnePlus 7T Pro is calibrated individually at the factory. The SEE sensor
registry values are specific to the unit and remain in `persist` after
unlocking and flashing; nothing should be copied from another handset or
shipped in a public package.

## Why this matters

Without the per-unit values, sensors run on the parser's defaults. On the
development unit that meant:

| group | default in use | this unit's factory value |
| --- | --- | --- |
| `lsm6dsm_0_platform.accel.fac_cal.bias` | `0.000000` on all three axes | `-0.086188`, `0.213099`, `0.035143` |
| `tcs3701_platform.als.fac_cal` `scale` | `1000.000000` | `1156.547607` |
| `tcs3701_platform.als.fac_cal` `cal_chh0..3`, `cal_chl0..2` | `1.000000` | `1.11` to `1.53` |

An uncompensated accelerometer and a light scale about fifteen per cent out.
Both still look like they work, which is what makes this easy to miss.

## Where the values live

`sns_reg.conf` names the location the sensor core writes back to:

```
file=output=/mnt/vendor/persist/sensors/registry/registry
```

That is the `persist` partition, `/dev/disk/by-partlabel/persist`, an ext4
volume of about 32 MB. It is not touched by unlocking or by flashing a new
system, so the factory registry survives — 438 group files on this device,
still carrying the values written on the production line.

## Do not copy calibration between phones

The numbers above belong to one unit. Applying them to another applies a wrong
bias with confidence, which is worse than applying none: an uncalibrated sensor
is at least neutral. The same is true of publishing a registry snapshot in a
package or a repository.

Each device must read its own.

## Importing

The packaged `/usr/libexec/hotdog-import-factory-calibration.py`, whose public
source is
[`hotdog-import-factory-calibration.py`](../aports/device/testing/device-oneplus-hotdog/hotdog-import-factory-calibration.py),
mounts `persist` read-only, compares it with the served registry, and copies
only what is missing.

```sh
hotdog-import-factory-calibration.py --essai   # show what would change
hotdog-import-factory-calibration.py           # apply
reboot                                         # the SLPI reads the registry at init
```

It is deliberately narrow:

- **only measured values.** The registry's `ver` field separates a value written
  by the factory, `ver` non-zero, from a default regenerated by the parser,
  `ver` `"0"`. Whole groups are never copied, because the factory registry comes
  from OxygenOS and also contains configuration this port changes on purpose.
- **only where the data differs.** A higher `ver` on the served side means the
  sensor core recalibrated since the factory; overwriting that with an identical
  older value would destroy a newer result for nothing.
- **group entries are skipped.** `type: "grp"` rows are containers with no value.
- **`persist` is mounted read-only** and never written.

Each modified group is backed up beside itself as
`<group>.avant-import-usine` before the first write.

## How calibration gets lost

Two ways, both seen here:

1. **Deleting files from `sensors/registry/`.** The parser recreates the group
   from the config JSON, which carries defaults. Remove a *config JSON* to drop
   a candidate sensor; never a registry group.
2. **The sensor core writing back a failed result.** `sns_tcs3701` rewrites
   `tcs3701_platform.prox.fac_cal` 21 seconds into every boot with zeroed
   offsets — what a failed offset calibration stores. That one is not recoverable
   by import, since the factory values are zero there too.

After any registry experiment, re-run the import in `--essai` mode. It is the
cheapest way to notice that something was quietly reset.

## Elliptic ultrasonic calibration

The ADSP Elliptic path has a separate 448-byte per-device calibration that is
not one of the SEE JSON registry groups. It is deliberately absent from Git and
from public release payloads. The sensor package provides
`/usr/libexec/hotdog-elliptic-calibration.py`: it restores a previously saved
value from `persist`, requires exactly 448 non-zero bytes and fails closed when
the value is absent or malformed.

On the reference handset, the already-active calibration was stored once under
`persist/hotdog/elliptic_calibration_v2.bin` and read back byte-for-byte. Other
handsets must provision their own value; copying the reference handset's blob
would violate the same per-unit rule as copying accelerometer or ALS biases.

## Checking without the tool

```sh
python3 -c '
import json
f = "/usr/share/qcom/sensors/registry/lsm6dsm_0_platform.accel.fac_cal.bias"
d = json.load(open(f))[list(json.load(open(f)))[0]]
print({k: (v["ver"], v["data"]) for k, v in d.items() if k != "owner"})'
```

`ver` `"0"` with `0.000000` means the default is in use. `ver` `"1"` with a
non-round number means the factory value is loaded.
