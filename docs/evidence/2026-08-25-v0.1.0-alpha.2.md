# v0.1.0-alpha.2 release validation

Alpha 2 is a clean rebuild from the current tracked package state. It replaces
Alpha 1 because the first public guide omitted the filtered `dtbo_b` that was
already installed on the development phone during the successful Alpha 1 boot.

the release was assembled: missing SMB5 bit definitions, missing PD-map
checksums, modules and firmware installed outside the runtime search paths,
and two transitional paths still expected by `mkinitfs`.

## Offline validation

- The split postmarketOS filesystems were assembled into a deterministic
  4096-byte-sector GPT image and both partitions passed complete readback
  hashing.
- `sgdisk --verify` and read-only `e2fsck -fn` passed.
- The boot and DTBO AVB footers and hash descriptors passed verification.
- The boot command line UUIDs match the GPT filesystems.
- The boot kernel and Hotdog DTB are byte-identical to the kernel APK payloads.
- `/boot.img` inside `pmOS_boot` is byte-identical to the release boot asset.
- The rootfs contains one module tree at `/lib/modules/6.16.0-sm8150` and the
  OxygenOS 10 MPSS plus SLPI 00083 payloads under `/lib/firmware`.
- The compressed archive passed `zstd -t`, decompressed to the recorded raw
  image hash, and every public asset passed `sha256sum -c SHA256SUMS`.

## Hardware scope

No phone partition was written during Alpha 2 packaging. A read-only check of
the connected development phone showed that it was still running the older
Alpha 1 filesystem UUID pair, so it was not used to claim an Alpha 2 boot. The
exact Alpha 2 artifact set is offline-validated and awaiting a supervised
hardware installation. Existing subsystem claims remain tied to their dated
hardware evidence, not to this packaging run.
