# Mainline 6.16 Adreno 640 validation

Date: 2026-08-04

Device: OnePlus 7T Pro HD1913 (`hotdog`)

Result: the source-built pmaports `r5` kernel enables the SM8150 Adreno 640,
loads the GMU and ZAP firmware, exposes a DRM render node, and completes real
Turnip Vulkan submissions after a direct boot from the OnePlus bootloader.

## Localization

The accepted `r4` image already contained the upstream SM8150 GPU, GMU,
Adreno SMMU, GPU clock controller, OPP table, and reserved-memory description.
Only the GPU and GMU status properties were disabled. A DT-only experiment
therefore changed exactly three semantic values:

- enable `gpu@2c00000`;
- enable `gmu@2c6a000`;
- select `qcom/sm8150/oneplus/hotdog/a640_zap.mbn` for the signed ZAP shader.

That experiment preserved the accepted `r4` kernel, initramfs, and command
line byte-for-byte. It direct-booted, returned USB SSH, loaded the GPU
firmware, exposed `/dev/dri/renderD128`, and completed two Vulkan workloads.
No additional regulator, clock, interconnect, IOMMU, or driver change was
required.

The result is carried in
`0017-arm64-dts-hotdog-enable-adreno640-gpu.patch`. The package validator now
also rejects builds without the required Qualcomm SCM, MDT loader, RPMh power
domain, SM8150 interconnect, GPU/GMU, Adreno SMMU, ZAP firmware, and reserved
memory contracts.

## Direct-boot attestation

The fresh boot reported:

```text
Linux hotdog 6.16.0-sm8150 #6-oneplus-hotdog-mainline616 SMP PREEMPT ...
boot_b sha256: 14da6a2e2f0b49b85eb1431f1c9e9e32a08250fa42149ebfd50881970bf9cf44
root: /dev/loop0p2 ext4 rw
usb0: up, carrier present
```

The source-built DTB then produced the following hardware state:

```text
gpu@2c00000 status: okay
gmu@2c6a000 status: okay
2c00000.gpu driver: adreno
/dev/dri/renderD128: present
available GPU frequencies: 257000000 345000000 427000000 499200000 585000000 675000000
```

The DRM driver loaded `qcom/a630_sqe.fw`, `qcom/a640_gmu.bin`, and GMU
firmware version `2.0.261`. The handset-specific signed ZAP image was available
at `qcom/sm8150/oneplus/hotdog/a640_zap.mbn`.

## Vulkan validation

`vulkaninfo --summary` selected the physical device below:

```text
deviceName = Turnip Adreno (TM) 640
driverName = turnip Mesa driver
driverInfo = Mesa 26.1.6
apiVersion = 1.3.354
```

`vkmark` then submitted two three-second headless workloads:

```text
[clear] duration=3.0: FPS: 10498 FrameTime: 0.095 ms
[cube] duration=3.0: FPS: 12175 FrameTime: 0.082 ms
vkmark Score: 11336
```

The devfreq statistics recorded four transitions and operation at the 675 MHz
top OPP during the workload. A post-test kernel log scan found no GPU hang,
GMU recovery, timeout, Adreno fault, or IOMMU fault. The touchscreen and USB
networking remained available after the test.
