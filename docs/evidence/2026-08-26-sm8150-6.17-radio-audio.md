## Hardware sequence

The boot image exercised on the phone used the same final source tree and DTB,
with Image SHA256
`91b5f954ab2214d2e6a61dd870d812a3ffceff1ff8a3a7f0f8df54f0480538be`
and AVB boot SHA256
`e9eaa3f1bf360b0c006b1396ae8e51bc028161f9b90d872c41bee298da2c1dde`.
The boot partition readback matched before reboot. The installed module hashes
also matched the package values above.

The first boot remained black with no framebuffer, gadget USB or SSH. After
about five minutes the operator pressed Volume Up and Power. That manual key
sequence exposed `05c6:9008` briefly and initiated the recovery/restart; the
9008 state was not an automatic crashdump recovery. No useful ramoops record
survived the failed boot.

The next boot of the same candidate reached a writable rootfs and SSH. The
kernel timeline was:

- root filesystem mounted at 4.629 seconds;
- IPA initialized and setup complete at 5.354 seconds;
- ADSP running from the hotdog firmware at 5.482 seconds;
- modem running from the hotdog firmware at 7.479 seconds;
- WCN3990 firmware startup complete at 13.135 seconds;
- `wlan0` associated at 21.292 seconds.

Runtime enumeration showed modem and ADSP both `running`, `rmnet_ipa0`,
`wlan0`, a 61-service QRTR inventory, and the `OnePlus 7T Pro` SM8150 sound
card. Both TFA9874 amplifiers, the FSA4480 mux, AW8697, touchscreen and fuel
gauge were bound to their expected drivers. A five-minute read-only stability
monitor retained the same boot identity and service count for all 30 samples.

## Verdict

`PARTIAL`: radio, IPA, Wi-Fi and audio enumerate and remain stable after the
manual restart, and the previous modem-related userspace wait is no longer
caused by missing firmware. The first black boot is unresolved. Promotion
requires another ordinary boot with no key sequence, reset or crashdump state.

No SIM, data session, call, SMS, audio playback, microphone, haptics or other
physical feature test was performed. Those tests remain deferred until the
complete migrated feature set is present.
