# IPA v4.1 on SM8150: what adding it actually requires - 2026-08-12

## Why this matters

The roadmap records mobile data as blocked behind IPA, and GNSS as blocked
behind the same thing, because the userspace location path needs a network
port that only rmnet over IPA provides. One driver unblocks two roadmap items.

## The gap is real, and it is narrow

Mainline 6.16 already knows this IPA generation exists. `ipa_version.h`
declares `IPA_VERSION_4_1` with its GSI 2.0 pairing. What it does not have is
anything to instantiate it:

- `drivers/net/ipa/data/` carries v3.1, v3.5.1, v4.2, v4.5, v4.7, v4.9, v4.11,
  v5.0 and v5.5. There is no `ipa_data-v4.1.c`.
- `ipa_main.c` matches msm8998, sdm845, sc7180, sdx55, sm6350, sm8350, sc7280,
  sdx65 and sm8550. There is no `qcom,sm8150-ipa`.

So this is not a port of a subsystem. It is one platform data file, one match
entry, a Makefile line, a binding and a device tree node.

## What the stock tree confirms

The live stock device tree pins the hardware down:

```
qcom,ipa@1e00000
	compatible      = "qcom,ipa"
	qcom,ipa-hw-ver = <0x0f>
	qcom,ee         = <0x00>
	reg             = <0x1e00000 0x34000>, <0x1e04000 0x28000>
	reg-names       = "ipa-base", "gsi-base"
	interrupt-names = "ipa-irq", "gsi-irq"
	qcom,use-64-bit-dma-mask
```

Downstream numbers its IPA generations in the same enum mainline mirrors, and
`0x0f` is 15, which is IPA v4.1. That agrees with SM8150 being the generation
between sdm845's v3.5.1 and sc7180's v4.2, and it means the two nearest
mainline data files sit on either side of the one to be written.

The firmware is present on the handset too: the reservation map carries
`pil_ipa_fw_region` and `pil_ipa_gsi_region`, so the loader has something to
load.

Note that the register layout is described differently downstream and
upstream. Downstream gives one `ipa-base` covering everything and a
`gsi-base` inside it; mainline splits the same space into `ipa-reg`,
`ipa-shared` and `gsi`. The node cannot be copied across, it has to be
translated.

## What is still missing, and where it comes from

The platform data file is not derivable from the device tree. It carries the
endpoint table, the resource group limits, the IPA-local memory region map and
the QSB read/write limits, and those live in the downstream IPA driver rather
than in any DT node. Guessing them is not an option: a wrong memory region map
does not fail cleanly, it corrupts.

That source is not in this checkout. Finishing this needs the downstream IPA
driver for SM8150, specifically its v4.1 endpoint, resource and memory tables.
Everything else on the path is settled.
