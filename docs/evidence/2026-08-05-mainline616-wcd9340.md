# Mainline 6.16 WCD9340 transport validation

Date: 2026-08-05

Device: OnePlus 7T Pro (`hotdog`), HD1913

Result: the isolated WCD9340 candidate direct-boots from the OnePlus
bootloader, preserves the running ADSP and MPSS remote processors, registers
the Qualcomm SLIMbus controller, identifies the physical codec, and binds its
MFD, GPIO, codec, and SoundWire drivers. This result does not yet claim an ALSA
sound card or working speaker, earpiece, microphone, headset, or Bluetooth
audio route.

## Scope

Revision `r24` adds the existing SM8150 WCD9340 description to the accepted
`r23` ADSP image. It supplies the stock-derived GPIO 123 interrupt, GPIO 143
reset, 9.6 MHz clock, and 1.8 V rails. The machine sound card and external
TFA98xx speaker amplifiers remain absent so this test isolates the codec
transport.

The package contract requires the SLIMbus regmap and Qualcomm NGD controller,
WCD9340 MFD/GPIO/codec drivers, and Qualcomm SoundWire controller. It also
checks every new DT phandle and rejects an accidentally enabled machine card.

## Hardware result

The fresh direct boot reports:

| Item | Observed value |
|---|---|
| Kernel build | `#25-oneplus-hotdog-mainline616` |
| Boot ID | `3d567999-e0a3-45ec-ad8d-ecc6bec6bb21` |
| ADSP state | `running` |
| MPSS state | `running` |
| SLIMbus controller | `171c0000.slim-ngd`, driver `qcom,slim-ngd-ctrl` |
| Codec device | `217:250:1:0`, driver `wcd934x-slim` |
| Codec identity | major `0x108`, minor `0x1` |
| SoundWire controller | `wcd934x-soundwire.3.auto`, v1.3.0 |
| USB recovery channel | NCM and SSH returned automatically |

SLIMbus enumerates both logical devices `217:250:0:0` and `217:250:1:0`.
The second binds to `wcd934x-slim` and creates bound `wcd934x-codec`,
`wcd934x-gpio`, and `qcom-soundwire` children. The SoundWire master appears as
`sdw-master-0-0`. The ADSP still registers APR services 3, 4, 7, and 8.

One `QMI wait timeout` is logged after controller registration, but codec
enumeration and every expected driver binding have already completed; a later
master-capability notification also arrives. This warning remains visible for
the next stage rather than being hidden.

`/proc/asound/cards` remains empty and Q6ASM still reports
`No dais found in DT`. That is the intended boundary: codec transport works,
but no machine topology yet connects DSP front ends to SLIMbus playback and
capture back ends. The codec also warns that headset-button voltage thresholds
are absent; those values must be derived before headset-button support is
claimed.

## Next gate

The next candidate may add the SM8150 machine sound card with a minimal set of
Q6ASM front ends and WCD9340 SLIMbus playback/capture back ends. It must first
produce a stable ALSA card with the internal codec only. External TFA98xx
speaker amplifiers and audio claims intended for normal use remain separate validation
gates.
