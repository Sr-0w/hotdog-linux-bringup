# Sensors SLPI AP STM ETF decode

This documents the public AP-side STM smoke decoder used for SENSORS-SLPI-51RE.
Private captures, exact run paths, runtime markers and proof hashes are kept in
the private log tree, not in Git. The examples below are synthetic.

## Evidence inputs

Use private evidence as external input only:

- capture: `<private-run>/<capture.bin>`;
- runtime proof: `<private-run>/script-run.txt`;
- expected marker: `<synthetic-or-private-marker>`;
- expected capture hash: `<sha256-from-private-manifest>`.

Do not commit capture bytes, device-specific run paths, exact runtime timestamps
or process IDs. Public tests use only synthetic ETF/STPv2 frames.

## Kernel emission path

The AP writer is Linux `p_basic`:

- `drivers/hwtracing/stm/p_basic.c` calls `stm_data_write(..., ts_first=true, ...)`;
- `drivers/hwtracing/stm/p_basic.c` appends one `STP_PACKET_FLAG` after a
  positive write;
- `drivers/hwtracing/stm/core.c` chunks the userspace write into logical STM
  data packets, with only the first chunk timestamped;
- `drivers/hwtracing/coresight/coresight-stm.c` caps each hardware data packet
  to the STM fundamental write size; the synthetic and private smoke paths decode
  as 32-bit data packets for full four-byte chunks;
- `drivers/hwtracing/coresight/coresight-stm.c` may enable hardware master
  override, so the decoded STP master can differ from the software policy master;
- `drivers/hwtracing/coresight/coresight-tmc-etf.c` can enable ETF formatting and
  trace-ID insertion, so the capture must be de-formatted before looking for STM
  payload bytes.

## Decoder

`scripts/decode_ap_stm_etf.py` implements the narrow decode required here:

1. split the capture into 16-byte formatted CoreSight frames;
2. reconstruct per-ATID payload streams from formatter ID/sideband bytes;
3. decode STPv2 nibbles in protocol order, low nibble then high nibble;
4. handle only the packet types generated by this smoke path: ASYNC, VERSION,
   FREQ, M8, C8/C16, D4/D8/D16/D32/D64 with or without timestamps, FLAG and NULL;
5. fail closed on malformed formatter data, truncated payloads, unsupported
   timestamp size `0xf` and reserved opcodes.

The helper is not a general replacement for OpenCSD.

## Timestamp handling

STPv2 timestamps are relative updates after the first full timestamp. The helper
prints three fields for timestamped packets:

- `timestamp_raw`: the timestamp bits carried by this packet;
- `timestamp_bits`: the number of raw bits in this update;
- `timestamp`: the reconstructed timestamp, or `None` if a partial update is
  seen before any full timestamp establishes the high bits.

For VERSION 3 the helper uses natural-binary reconstruction. For VERSION 4 it
reconstructs through Gray-code state. Partial updates replace the low
`timestamp_bits` of the previous timestamp, matching OpenCSD/Zephyr decoder
semantics; they are not printed as absolute timestamps. The public regression
cases are:

- VERSION 3 natural-binary: full 64-bit `0x123456789abcdef0`, then 8-bit raw
  update `0x5a`, reconstructing to `0x123456789abcde5a`;
- VERSION 4 Gray-coded: full raw `0x08913ba26ef75dc4`, decoding to
  `0x0f1e2d3c4b5a6978`, then 8-bit raw update `0x3c`, reconstructing to
  `0x0f1e2d3c4b5a69d7`.

## OpenCSD cross-check

The private AP ETF capture was cross-checked against OpenCSD:

- repository: <https://github.com/Linaro/OpenCSD>;
- commit: `59f15320637ce6e510604e7bed550d7ad109d15d`;
- tree: `302aa77dfae81280a856172f7eb1e4e1f53c0f12`.

Build:

```sh
git clone --no-checkout https://github.com/Linaro/OpenCSD.git <opencsd-worktree>
cd <opencsd-worktree>
git checkout 59f15320637ce6e510604e7bed550d7ad109d15d
cmake -S . -B <build-dir> -DCMAKE_BUILD_TYPE=Release
cmake --build <build-dir> --target trc_pkt_lister
```

At this OpenCSD commit the target is built by the top-level project but the
test binary is emitted under `decoder/tests/bin/builddir/` in the OpenCSD
worktree.

Minimal snapshot directory for an already-formatted CoreSight ETF capture:

`snapshot.ini`

```ini
[snapshot]
version=1.0

[device_list]
device0=device_0.ini

[trace]
metadata=trace.ini
```

`trace.ini`

```ini
[trace_buffers]
buffers=buffer1

[buffer1]
name=ETB_1
file=<capture-file-name>
format=coresight

[source_buffers]
STM_0=ETB_1

[core_trace_sources]
```

`device_0.ini`

```ini
[device]
name=STM_0
class=trace_source
type=STM

[regs]
STMTCSR(0x3A0)=0x00010007
```

The synthetic `STMTCSR` value above selects CoreSight trace ID 1 using the
OpenCSD STM trace-ID field:

```text
STMTCSR = (trace_id << 16) | flags
        = (0x01 << 16) | 0x00000007
        = 0x00010007
```

Run `trc_pkt_lister` with the private capture as an external input:

```sh
cd <scratch-output-dir>
<opencsd-worktree>/decoder/tests/bin/builddir/trc_pkt_lister \
  -ss_dir <stm-only-snapshot-dir> \
  -o_raw_unpacked -decode -id 1 -src_name ETB_1 \
  -logstdout -no_time_print
```

`-src_name` is the snapshot source name (`ETB_1` in `trace.ini`), while the
private capture path is supplied by `file=<capture-file-name>` in `trace.ini`.
Run from a scratch output directory because OpenCSD may create a packet-listing
log file in the current directory.

Expected output shape, with private payload bytes omitted:

```text
Trace Packet Lister : Protocol printer STM on Trace ID 0x1
Frame Data; Index <n>; ID_DATA[0x01]; <formatted bytes omitted>
Idx:<n>; ID:1; ... ASYNC:Alignment synchronisation packet
Idx:<n>; ID:1; ... VERSION:Version packet; Ver=3
Idx:<n>; ID:1; ... FREQ:Frequency packet; Freq=0Hz
Idx:<n>; ID:1; ... M8:Set current master; Master=<hardware-master>
Idx:<n>; ID:1; ... C16:Set current channel; Chan=<policy-derived-channel>
Idx:<n>; ID:1; ... D32TS:32 bit data + timestamp; Data=<omitted>; TS=<omitted>
Idx:<n>; ID:1; ... D32:32 bit data; Data=<omitted>
Idx:<n>; ID:1; ... FLAG:Flag packet
```

For this trace shape, candidate trace ID `1` decodes the STM payload. Candidate
ID `0` is formatter padding/metadata and is classified as `zero-padding`, not AP
STM payload.

## Usage

```sh
python3 scripts/decode_ap_stm_etf.py \
  <private-capture.bin> \
  --expect-sha256 <sha256-from-private-manifest> \
  --expect-marker '<expected-marker>'
```

Exit codes:

- `0`: decode succeeded and the marker matched, or no marker was requested;
- `1`: decode succeeded but `--expect-marker` did not match any decoded STP
  payload;
- `2`: input read error, hash mismatch, malformed ETF/STPv2 stream, unsupported
  opcode, unsupported timestamp encoding, truncated packet, empty capture or
  capture with no useful STP stream.

## Synthetic decoded sequence

A synthetic p_basic-style marker on policy channel 10 decodes like this:

| # | Type | STP master | STP channel | Payload | Timestamp |
|---|---|---:|---:|---|---|
| 00 | ASYNC | 0x00 | 0x0000 | | |
| 01 | VERSION | 0x00 | 0x0000 | 3 | |
| 02 | FREQ | 0x00 | 0x0000 | | |
| 03 | M8 | 0x40 | 0x0000 | | |
| 04 | C16 | 0x40 | 0x280a | | |
| 05 | D32_TS | 0x40 | 0x280a | `PUBL` | reconstructed |
| 06 | D32 | 0x40 | 0x280a | `IC_S` | |
| 07 | D32 | 0x40 | 0x280a | `TM_T` | |
| 08 | D32 | 0x40 | 0x280a | `EST\n` | |
| 09 | FLAG | 0x40 | 0x280a | | |

The configured software policy channel is 10. The decoded channel low byte is
therefore expected to be `0x0a`. The decoded master can be hardware-selected
when STM hardware override is active.

## Verdict

The AP ETF smoke capture is not directly searchable as ASCII. Payload bytes are
carried inside formatted CoreSight frames and STPv2 nibble encoding. A marker is
proved only after ETF de-formatting, STPv2 packet decode, ATID selection and
payload reconstruction agree with the expected marker.
