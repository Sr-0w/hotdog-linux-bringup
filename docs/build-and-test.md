# Build and test workflow

This document contains the detailed build, packaging, image-assembly, and test
commands that were previously kept in the repository root `README.md`.

## Getting started

Clone the repository and inspect the host without touching a phone:

```bash
git clone https://github.com/Sr-0w/hotdog-linux-bringup.git
cd hotdog-linux-bringup
./scripts/bootstrap-host.sh
```

Fetch the external source trees:

```bash
./scripts/bootstrap-sources.sh --sm8150-k1
cp pmbootstrap_v3.cfg.example pmbootstrap_v3.cfg
cp hotdog.env.example hotdog.env
./scripts/check-host-tools.sh
./scripts/build-mainline-k1-dtb-chain.sh
```

The hardware-tested V30 direct-display kernel can be rebuilt byte-for-byte
from the pinned ClearStaff commit, the public patch series, and the checked-in
kernel configuration:

```bash
./scripts/prepare-clearstaff616-source.sh
./scripts/build-clearstaff616-v30-kernel.sh
```

The build stops unless the selected source files, generated configuration, and
final arm64 `Image` match their recorded SHA256 values. The separate
`build-clearstaff616-v30-dynamic-pps.sh` packager also validates its DTB, DTBO,
initramfs, command line, and Android boot-image inputs; those earlier
bring-up artifacts are not yet all regenerated by one clean public command.

The current package-to-hardware milestone can be reproduced from the pinned
pmaports revision after copying the curated aport snapshots into that checkout:

```bash
git -C src/postmarketos/pmaports checkout \
  918a1f4e4dd1ebcf0e4df226dbadc210a857fe9c
./scripts/sync-aport-snapshots.sh --apply --to-pmaports \
  --target-pmaports "$PWD/src/postmarketos/pmaports"
HOTDOG_PMAPORTS_SM8150="$PWD/src/postmarketos/pmaports" \
HOTDOG_PMBOOTSTRAP_WORK="$PWD/pmbootstrap-work-current" \
./scripts/pmbootstrap-hotdog.sh -j 32 install --split --no-sparse \
  --add polkit-elogind
```

Device package `3-r7` installs a `boot-deploy` postprocess hook, so the normal
install command above emits the final 100,663,296-byte, header-v2 AVB image
without a separate wrapping step. The hook derives its salt from the raw image,
uses the `boot` partition name and `NONE` algorithm, then verifies the final
size, footer, descriptor, salt, and original image size. The exact package and
filesystem identities from the validated builds are in the
[2026-08-03 pmaports evidence](evidence/2026-08-03-mainline616-pmaports.md)
and [clean public-image evidence](evidence/2026-08-05-mainline616-public-image.md).

The standalone wrapper remains available for validating or converting older
raw artifacts without modifying the input:

```bash
./scripts/wrap-pmaports-boot-avb.sh \
  --boot-image /path/to/generated/boot.img \
  --outdir build/pmaports-mainline616-avb
```

It rejects incompatible headers, load addresses, command lines, and partition
sizes, then verifies the AVB footer and records component hashes. It is not
required for images generated by device package `3-r7` or later.

Assemble the matching split filesystems into the deterministic nested GPT used
for the first hardware validation:

```bash
./scripts/assemble-pmaports-subpartition-image.sh \
  --boot-image /path/to/oneplus-hotdog-boot.img \
  --root-image /path/to/oneplus-hotdog-root.img \
  --outdir build/pmaports-mainline616-subpartitions
```

The assembler runs offline, validates the filesystem labels and UUIDs, creates
exactly two 4096-byte-sector GPT partitions, and hashes both complete partition
readbacks. It never accesses a phone; deploying the resulting image remains a
separate, destructive hardware operation.

The repository does not distribute ready-to-flash boot images. Generated
kernels, initramfs archives, phone dumps, logs, and source checkouts stay in
ignored local directories. Follow [host-setup.md](host-setup.md),
[artifacts.md](artifacts.md), and
[device-safety.md](device-safety.md) before any hardware operation.

Once the hash-pinned artifacts have been built or restored, the complete
mainline cycle is launched with:

```bash
./scripts/test-mainline617-pmos-full.sh
```

That launcher hash-checks the kernel, DTB, initramfs, and restore image before
transferring control to mainline.

The complete K1 DTB chain is reproducible from a clean source checkout and
tracked inputs. The launcher remains a lab replay until the kernel, initramfs,
and Android boot image are also produced entirely through the tracked pmaports
packages.
