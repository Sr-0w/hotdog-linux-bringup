What the backport changes
  It is the upstream delta, retargeted:
    file qcom_pmi8998_charger.c
    symbols smb2_*
    dev_pm_set_wake_irq() left as the 6.12 call
  It adds SMB2_FLOAT_VOLTAGE_MAX_UV (4920000) beside the queued
  minimum and step. It does not repeat the off-by-one removal.
  Float selection prefers constant_charge_voltage_max_uv, then
  voltage_max_design_uv. If neither optional property is present,
  the hardware setting is kept. A supplied target outside
  3487500..4920000 uV fails probe with -EINVAL.
  In-range values use integer division by 7500 and truncate toward
  zero. That is the upstream behavior; unaligned targets are not
  rejected.
  smb2_init_hw() still sets CHARGING_ENABLE_CMD before battery data
  is read. The backport saves that bit first and restores it with
  devm_add_action_or_reset() if a later probe step fails. On success,
  after dev_pm_set_wake_irq(), devm_remove_action() drops the
  rollback so a successful probe does not undo charging.
  v6.12.116 already has power_supply_battery_info_has_prop(),
  initializes absent optional voltages to -EINVAL, and treats a
  value >= 0 as present. Those helpers were not backported here.

Remaining risks
  Bare v6.12.116 rejects this patch until the queued selector
  backport is applied. If that queue patch is dropped or edited,
  this backport has to be regenerated.
  Unaligned in-range voltages are truncated down to a 7500 uV step.
  That matches upstream and can program a lower float voltage than
  the devicetree number.
  Probe failure restores the pre-probe charging bit. Successful
  probe leaves the bit set by smb2_init_hw(). Neither path was run
  on SMB2 hardware.
